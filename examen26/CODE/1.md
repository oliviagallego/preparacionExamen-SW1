# SIMULACRO — Sistemas Web I — PARTE PRÁCTICA (2 horas, papel)

## Contexto

Se desea una **mini aplicación web** con **Node.js + Express + EJS** para gestionar usuarios con roles y un **panel admin**. Además, el panel admin recibirá **notificaciones en tiempo real** con **Socket.IO** cuando alguien inicia sesión o cuando un admin elimina un usuario.

* Datos en memoria (NO BD real).
* Se usa **express-session** para recordar el usuario logueado.
* La estructura se debe respetar.
* Se valorará que el HTML sea correcto y que las vistas EJS recorran correctamente **arrays/objetos**.

# Tareas a completar

## Apartado 1 — Arranque del servidor + Socket.IO (1,5 puntos)

En `bin/www`:

1. Configura el puerto como `process.env.PORT` o `3000`.
2. Crea el servidor HTTP con `http.createServer(app)`.
3. Arranca escuchando y muestra por consola el puerto.
4. Inicializa Socket.IO usando `initSockets(server)`.

---

## Apartado 2 — Configuración Express (1 punto)

En `app.js`:

1. Configura **EJS** como motor de plantillas y la carpeta `views`.
2. Configura `public` como estáticos.
3. Configura el parseo de formularios (`express.urlencoded`).
4. Configura sesión con `express-session`.
5. Crea un middleware que deje accesible el usuario logueado en `res.locals.currentUser` para todas las vistas.

---

## Apartado 3 — Login/Logout (2 puntos)

En `routes/auth.js`:

1. `GET /login` renderiza `login.ejs`.
2. `POST /login`:

   * Recibe `username` y `password`.
   * Valida contra `database.js`.
   * Si OK: guarda usuario en sesión (`req.session.user = ...`), actualiza `last_login` y redirige a `/`.
   * Si NO: re-renderiza login con error.
   * Cuando el login sea correcto, emite un evento socket **solo a admins**: `io.to("admins").emit("admin:notice", ...)`
3. `POST /logout`: destruye sesión y redirige a `/`.

---

## Apartado 4 — Panel Admin + control de acceso (2,5 puntos)

En `routes/admin.js`:

1. Crea middleware `requireAdmin` usando `next`:

   * Si no hay sesión: redirect `/login`
   * Si hay usuario pero no es admin: redirect `/`
   * Si es admin: `next()`
2. `GET /admin` (protegida con `requireAdmin`) renderiza `admin.ejs` pasando:

   * `users` (lista de usuarios)
3. `POST /admin/delete` (protegida con `requireAdmin`):

   * Recibe `username`.
   * NO permitir borrar:

     * al propio admin logueado
     * a un usuario con role `admin`
   * Si se borra: emitir a room admins: `admin:notice` y redirigir a `/admin`.

---

## Apartado 5 — Socket.IO rooms + cliente admin (2 puntos)

En `sockets.js`:

1. Cuando un cliente se conecta, escucha el evento `client:joinAdmins`:

   * Si el payload contiene `{ token: "admin" }`, mete ese socket en la room `"admins"`.
2. Expón una función `getIO()` para poder emitir desde rutas.

En `views/admin.ejs`:

1. Conecta con socket.io en cliente.
2. Al cargar, emite `client:joinAdmins` con `{ token: "admin" }`.
3. Escucha `admin:notice` y muestra el mensaje en una zona `<div id="notices">`.
